ⓘ How detection works

The scanner sends 4 HTTP request chains to the target and compares responses:

MAIN — baseline GET {url}
OFFER_TEST — GET {url}?_lp=1&_token=invalid
CLICK_API — GET {origin}/click_api/v3
UPDATE_TOKENS — GET {origin}/?_update_tokens=1

Each response is analyzed through 7 independent evidence checks, each tied to official Keitaro documentation.

★ 7 Evidence Checks

E1 Offer URL params: _lp + _token/token docs →

Searches all URLs and Location headers across all chains for query params _lp + _token/token. Keitaro Offer URL (LP→Offer) uses these as documented.

E2 Landing redirect params: _subid + _token/token docs →

Searches all URLs and Location headers for _subid + _token/token. Keitaro landing redirect adds these before redirecting to landing page.

E3 Cookie: Set-Cookie contains "subid=" docs →

Keitaro Tracking Script stores click id in cookie subid. Scanner checks all Set-Cookie headers across all chains. Requires CF Worker — CORS proxies cannot forward cookies.

E4 HTML markers: KTracking / {subid} / {offer} docs →

Official Keitaro tracking script uses KTracking API and placeholders {subid} / {offer}. Scanner searches HTML bodies of all chain responses.

E5 API: /click_api/v3 exists (non-404 + JSON) docs →

Keitaro has a documented public Click API at /click_api/v3. Scanner sends request with invalid token. Non-404 + JSON-like response indicates the endpoint exists.

E6 Behavior: reacts to Offer URL params (_lp + _token) docs →

Compares MAIN vs OFFER_TEST first HTTP response: status, content-type, location, body length. Any difference means the server understands Keitaro-specific params.

E7 Behavior: reacts to _update_tokens=1 docs →

Compares MAIN vs UPDATE_TOKENS first HTTP response: status, content-type, location, body length. _update_tokens=1 is a documented mechanism for updating click params (can return empty response).

⚖ Verdict

≥2 KEITARO CONFIRMED — multiple independent documented evidences
1 NOT CONFIRMED — only 1 evidence, need ≥2 (can be coincidental)
0 NOT DETECTED — no documented evidences found

⚙ What is Keitaro TDS?

Keitaro is a commercial Traffic Distribution System (TDS) that routes visitors by geo, device, OS, referrer, etc. Legitimate product, but widely abused to cloak phishing, malware, and scam pages — showing clean content to bots and malicious content to real victims.
