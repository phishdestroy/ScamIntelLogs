What is Keitaro TDS?

Keitaro is a Traffic Distribution System - software designed to show different content to different visitors. In practice, this means:

👮 Moderators See

Legitimate content: news articles, blogs, empty pages, or "under construction" messages

👤 Victims See

Malicious content: crypto scams, phishing pages, malware downloads, fake shops

This is called "cloaking" - and it exists solely to deceive platform moderators and security systems.

Why We Believe This Cannot Be Legitimate

  • DECEPTION Core purpose is hiding content from reviewers - no legitimate business needs this
  • AVCHECK Direct ties to malware testing services - used to test malware against antivirus
  • MALWARE Linked to multiple malspam campaigns - banking trojans, ransomware distribution
  • FORUMS Advertised on cybercrime forums - Russian-speaking underground markets
  • STRUCTURE Russian devs, Estonian company - jurisdiction shopping to avoid takedowns

🔬 Detection Methods

Our script uses 7 detection techniques based on official Keitaro documentation:

  • API Click API - Tests /click_api/v3 endpoint response
  • PARAMS Offer Reaction - Checks response to _lp and _token params
  • TOKENS Update Tokens - Tests _update_tokens=1 behavior
  • URL Offer Params - Looks for characteristic URL parameters
  • COOKIE Subid Cookie - Detects tracking cookies
  • HTML HTML Markers - Finds KTracking, {subid}, {offer} in source
  • LANDING Landing Params - Identifies _subid + _token patterns

Verdict: ≥2 evidences = KEITARO CONFIRMED

For Security Researchers

Signs a site uses Keitaro cloaking:

  • /admin redirects to Keitaro login page ("Welcome!")
  • URLs contain _lp=1, _token=, _subid= parameters
  • Different content from datacenter IPs vs residential IPs
  • /click_api/v3 endpoint returns JSON (even if error)
  • Cookies named subid or similar tracking identifiers
