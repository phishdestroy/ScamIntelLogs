⚠ Scam-the-Scammer Assessment

This panel has a high probability of stealing funds from its own workers. Drainer reseller panels are notorious for this pattern — they recruit workers (traffers), let them drive victims, then silently redirect stolen funds to the operator. This is extremely common: scammers scamming scammers.

Server-Side Transaction Building

Verdict: Either will steal from workers after first significant drain, or is already doing so. The panel architecture is designed for the operator to have complete control over all funds. Typical pattern for reseller-grade drainers.

Decrypted Code Analysis

script.js — Loader & Anti-Analysis (68 lines)

Entry point injected into victim's phishing page. Responsibilities:

  • Anti-Debug IIFE — recursive function with debugger statement, called via setInterval every 1000ms. Uses division trick (("" + x/x).length !== 1) to alternate between (function(){}).constructor("debugger")() and direct debugger keyword
  • Console Hijacking — Object.defineProperty(window, "console", ...) replaces all 5 console methods (log, warn, error, info, debug) with empty functions
  • XOR-Encrypted Config — window.config set to Base64-encoded XOR-encrypted JSON blob containing all drainer settings (spoof text, wallet details, notification preferences)
  • Script Chain Loading — sequentially loads: walletconnect-bundle.js (1.1MB WalletConnect SDK), axios@1.6.7, then script_tron.js?v=29 (drainer core), then wallet-modal.js?v=29 (fake UI)
  • UI Injection — injects CSS styles for loading overlay, low-balance error modal, and sign-waiting modal into page DOM
  • Button Binding — finds all elements with class connectWallet and binds click handlers to open the fake wallet modal

script_tron.js — Core TRON Drainer (525 lines)

Main drainer engine. All communication with trump-drop.world is XOR-encrypted with key TRX_SECURE_2024_PANEL_KEY.

Key Functions:

xorConvert(data, key)

Dual-mode XOR cipher. Detects Base64 input via regex, decodes if needed, XORs each char with key (cycling), returns Base64 or plaintext. Used for ALL API request/response encryption.

sendNotification(type, extras)

XOR-encrypts payload and POSTs to /api/notification. Types: joined, selected_wallet, connection, approved, drain, error, etc. Sends session ID + full encrypted config with every notification.

connectWalletConnect()

Server-Side Events (SSE) connection to /api/fetchWalletConnect. Server generates WalletConnect pairing URI, client opens official WC modal with it. Listens for events: connection (show QR), wallet (show signing UI), signed (done), error. Uses project ID fbf5b42d6feed07049dd9e59d888645a.

connectTronLink()

Multi-provider detection: checks window.bitkeep.tronWeb, window.tronWeb, window.tronLink in sequence. On mobile: attempts tron_requestAccounts with 1s/2s wait delays. Falls back to TronLink deeplink protocol. On desktop: uses TronWalletAdapters.TronLinkAdapter.

processWalletConnection(address, walletName, adapter)

Core malicious function. XOR-encrypts wallet address + config, POSTs to /api/buildTransactions. Server returns crafted malicious transactions. Then enters forced signing loop: 50 attempts with 500ms delay. Tries adapter.signTransaction, wcAdapter.signTransaction, or tronWeb.trx.sign. If victim rejects — immediately retries. Signed transaction sent to /api/sendTransaction.

init() + Mobile Auto-Connect

On mobile devices, after 1.5s delay, automatically attempts to connect without user interaction. Checks Bitget (bitkeep), imToken (UA sniffing), then generic TronLink. If wallet provider found — calls processWalletConnection directly, bypassing the modal entirely. Victims opening the page in a wallet browser get drained automatically.

walletDeeplinks{}

Deeplink URLs for 7 wallets: Trust (link.trustwallet.com), OKX (okx://wallet/dapp), TokenPocket (tpdapp://open), SafePal (link.safepal.io), MathWallet (mathwallet://), Bitget (bkcode.vip), imToken (imtokenv2://). On mobile, clicking a wallet opens the scam page inside that wallet's browser — triggering auto-connect.

Attack Flow

  1. Victim lands on fake TRX airdrop page with drainer scripts injected in <head>
  2. Loader (script.js) activates anti-debug traps and decrypts XOR config
  3. On mobile: auto-connect triggers after 1.5s if wallet browser detected (Bitget, imToken, TronLink)
  4. On desktop: victim clicks "Connect Wallet" — sees professional-looking fake wallet modal
  5. Wallet selected → selected_wallet notification sent to operator via Telegram
  6. Connection established via WalletConnect QR / TronLink extension / deeplink to wallet app
  7. Wallet address + encrypted config sent to /api/buildTransactions on trump-drop.world
  8. Server returns crafted malicious transactions. Victim sees fake: "Receive 10,000 TRX ($2,200)" with "verified" badge
  9. Forced signing loop: 50 retry attempts, 500ms interval. Victim must close browser to escape
  10. Signed transaction submitted to blockchain via /api/sendTransaction
  11. TRX + USDT drained from wallet. 30 TRX auto-commission to operator. Telegram notification dispatched
